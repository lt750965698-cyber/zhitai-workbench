# 开始使用

本指南只启动织台仓库自带的核心，不安装或登录任何第三方平台。完成后可以访问工作台、本地健康接口和知识库基础能力；其他模块会保持未配置状态。

## 1. 环境要求

- Node.js 22.13.0 或更高版本；
- pnpm 11.19.0 或更高版本，建议通过 Corepack 启用；
- Git；
- 至少两个终端窗口。

主要开发验证环境为 macOS。Linux 可用于核心与 CI 测试。原生 Windows 可以尝试运行本地节点，但 dev、build、start 当前使用 POSIX 环境变量语法，桌面启动脚本、系统钥匙串和部分媒体探测也未适配，因此完整快速开始需要 POSIX shell。

确认版本：

~~~bash
node --version
corepack --version
~~~

## 2. 获取代码

~~~bash
git clone https://github.com/lt750965698-cyber/zhitai-workbench.git
cd zhitai-workbench
corepack enable
pnpm install --frozen-lockfile
~~~

如果 Corepack 不可用，请按 Node.js 官方方式安装 pnpm，不要在项目中提交全局包管理器配置或注册表凭据。

## 3. 创建本地配置

~~~bash
cp local-agent/config.example.json local-agent/config.local.json
~~~

local-agent/config.local.json 已在 Git 忽略规则中。仍需在首次运行前检查：

- host 使用 127.0.0.1；当前 Web 与桌面客户端固定连接 127.0.0.1:17890，不要改成 localhost 或 ::1；
- port 默认是 17890；
- knowledgeBase 指向你有权读写的本地目录；
- allowedOrigins 只包含实际使用的本地页面来源；
- adapters 和 services 中的外置能力保持关闭或未配置；
- 所有示例路径必须替换为自己的安装位置，不能照抄占位符。

不要把 Token、Cookie、二维码、手机号、账号 ID 或密钥直接写入可提交文件。Webhook 密钥优先使用系统钥匙串；无钥匙串环境可使用权限受限的本地文件或短期环境变量。

## 4. 启动核心

终端 A：

~~~bash
pnpm agent
~~~

看到本地节点开始监听后，在终端 B 运行：

~~~bash
pnpm dev
~~~

页面端口由开发服务器输出，通常为 http://localhost:3000。确认健康状态：

~~~bash
curl http://127.0.0.1:17890/health
~~~

如果页面无法调用节点，检查浏览器地址是否已加入 allowedOrigins。不要为了省事使用通配来源，也不要把节点绑定到 0.0.0.0。

## 5. 无外置引擎时的预期

以下行为是正常的：

- 工作台和本地节点启动；
- 知识库可以创建索引和显示本地数据；
- 未配置的采集、分析、生成、通知和发布模块显示未配置、不可用或需要处理；
- 服务状态中可能出现未安装的可选组件；
- 不会自动登录平台、下载内容或公开发布。

如果某个未配置模块显示为成功或健康，请提交缺陷报告。

## 6. 开发检查

~~~bash
pnpm lint
pnpm test
~~~

pnpm test 包含生产构建和 Node.js 测试。默认测试必须使用临时目录、合成数据和模拟适配器，不访问真实平台。

常用单项命令：

~~~bash
pnpm build
pnpm test:agent
~~~

## 7. 桌面外壳

Electron 外壳仍是 Public Preview，当前不提供稳定签名发行包。开发者可在确认 Electron 依赖和本地权限后进入 desktop 目录运行其脚本；它不是核心快速开始的必需步骤。

桌面壳拥有比浏览器页面更多的本机能力，包括受限 IPC、打开本地窗口和部分浏览器自动化。调试时不要扩大 IPC 白名单，也不要把任意 URL、命令或路径直接转发给主进程。

## 8. 启用外置集成

在启用任何集成前：

1. 阅读 [第三方声明](../THIRD_PARTY_NOTICES.md)；
2. 从官方上游自行取得固定版本；
3. 检查许可证、服务条款、网络请求和数据处理；
4. 在隔离环境中安装，并限制为回环访问；
5. 只使用你有权操作的账号和内容；
6. 先运行健康检查和草稿流程；
7. 验证人工审核与停止路径，再考虑更高权限动作。

织台界面中的可选模块更新器在显式确认后也可以从已配置的 GitHub 上游下载组件。当前更新器会核对发布标签、内部版本和部分资产大小，个别更新清单使用 MD5，但没有为所有上游提供发布者签名或 SHA-256 验证。它还可能安装依赖；MatrixMedia 流程会修改 Info.plist 并进行本机 ad-hoc 重签名。把该流程视为便利功能而不是供应链证明，生产使用前应独立核验上游资产。

详细配置见 [集成指南](INTEGRATION.md)。

## 9. 排错

### 本地节点启动失败

- 检查 Node.js 版本；
- 检查 config.local.json 是否为有效 JSON；
- 确认 host 是回环地址；
- 确认端口未被占用；
- 确认 knowledgeBase 和 dataDir 可写；
- 临时关闭所有外置 services，缩小问题范围。

### 页面显示引擎不可达

- 确认 pnpm agent 仍在运行；
- 使用 curl 检查健康接口；
- 核对页面实际来源与 allowedOrigins；
- 检查浏览器控制台是否为 CORS 或混合内容错误。

### 外置模块显示未安装

这是安全默认值。不要把任意下载脚本粘贴到终端。请按上游官方文档安装固定版本，再配置明确的可执行文件、工作目录和回环健康地址。

### 数据迁移或内容库异常

停止写入，先备份数据库与内容包，再用最小副本复现。不要在没有备份的情况下删除、移动或批量重写真实素材。

## 10. 清理本地开发数据

项目运行会在配置的数据目录和知识库目录写入状态。删除前先确认精确路径和备份需求。不要对主目录、工作区根目录或未解析变量运行递归删除命令。
