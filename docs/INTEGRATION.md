# 第三方集成指南

织台使用可替换适配器连接第三方采集、分析、生成、通知和发布能力。集成是可选项；核心启动不依赖任何平台账号。

本指南只描述接口和安全要求，不提供第三方源码、登录态或一键打包。启用前先阅读 [第三方声明](../THIRD_PARTY_NOTICES.md)。

## 集成类型

| 类型 | 织台侧职责 | 外置侧职责 |
| --- | --- | --- |
| 采集 | 校验来源、排队、媒体收据、内容包入库 | 合法取得媒体或稳定元数据 |
| 分析 | 调度、保存来源与置信度、明确 unavailable | ASR、OCR、镜头、视觉或音频分析 |
| 生成 | 方案、任务、回收产物、人工审核 | 图像、视频、配音、字幕或合成 |
| 通知 / 远程控制 | 固定命令、来源绑定、可配置且配置后强制的 HMAC 校验、审计 | 可靠传输与账号会话 |
| 发布 | 素材边界、草稿模式、确认门、收据 | 平台登录、草稿或发布动作 |
| 业务辅助 | 服务互斥、健康状态、最小权限 | 监控、客服或账号管理 |

## 配置原则

local-agent/config.example.json 只是一份安全示例。复制到 config.local.json 后逐项填写自己的路径。

一个受管理服务通常包含：

~~~json
{
  "label": "示例外置服务",
  "role": "analysis",
  "project": "upstream-project",
  "projectUrl": "https://github.com/example/upstream",
  "installChecks": [
    "/absolute/path/to/a/verified/executable"
  ],
  "healthUrl": "http://127.0.0.1:19000/health",
  "start": {
    "command": "/absolute/path/to/a/verified/executable",
    "args": [
      "--host",
      "127.0.0.1",
      "--port",
      "19000"
    ],
    "cwd": "/absolute/path/to/a/verified/checkout"
  }
}
~~~

要求：

- command、args 和 cwd 来自本地配置，不能来自浏览器请求；
- 使用参数数组和 shell false，禁止拼接任意 shell 字符串；
- healthUrl 与 baseUrl 只能使用回环地址；
- 路径先解析真实路径，再检查是否位于允许根目录；
- installChecks 只表示文件存在，不等于服务健康或账号已登录；
- 手工安装时应固定上游版本，并记录许可证与可验证的校验和；
- 更新不得覆盖用户配置、登录态或未提交修改。

织台的可选模块更新器是便利功能，不是完整供应链验证。它读取固定上游的 latest release，把下载地址约束到精确 GitHub owner、仓库、tag 与路径，并要求二进制资产、热更新清单及其文件通过 SHA-256；缺失时拒绝更新。GitHub 自动生成的源码归档仍没有统一 Release digest，项目也没有为所有组件验证发布者签名。MatrixMedia 流程还会修改 Info.plist 并执行本机 ad-hoc 重签名。使用者必须在确认更新前自行核验上游资产与许可证。

## 生命周期状态

集成状态应区分：

- not_configured：用户尚未填写必要配置；
- not_installed：配置存在但程序不存在；
- stopped：已安装但未运行；
- running：进程存活，尚未证明业务可用；
- healthy：健康契约通过；
- needs_attention：需要登录、验证码、授权或人工处理；
- degraded：部分能力可用；
- failed：明确失败；
- optional：不影响核心运行。

不要把端口开放、进程存活或退出码 0 单独当成业务成功。

## 采集适配器

采集输入至少应归一化为：

- 稳定来源 URL 或本地文件；
- 平台与内容 ID（如果可验证）；
- 接收通道；
- 媒体文件或下载收据；
- 可选元数据及其来源；
- 采集时间和失败原因。

临时下载 URL 只能在下载期间存在。Token、Cookie、签名参数、解密键和完整上游响应必须从公共 metadata、日志、事件和 API 中剥离。

媒体入库应经过：

1. 来源和域名校验；
2. 下载大小、超时和内容类型限制；
3. 媒体签名或探测；
4. SHA-256；
5. 临时目录写入；
6. 同文件系统原子移动；
7. SQLite 幂等更新。

分享页面不是媒体文件。无法取得合法媒体时，应等待主适配器、返回失败或要求人工提供文件，不得把 HTML 保存为成功视频。

## 分析适配器

分析结果必须包含 provider、providerVersion、observedAt、status 和错误或缺失能力。

- ASR 没有运行时，transcript 为 unavailable；
- 没有 OCR 或关键帧时，不生成画面文字；
- 没有镜头检测和视觉证据时，不声称具体景别、机位或运镜；
- 没有播放、完播、留存和基准时，不声称爆火因果；
- 模型推断必须与可观察事实分层保存。

## 生成适配器

生成服务只接收使用者明确选择且有权处理的素材。记录上传范围、模型、版本、提示词摘要和产物来源。

生成完成后进入本地草稿：

- 检查版权、肖像、商标、事实和平台政策；
- 检查字幕、配音、画面瑕疵和生成标注；
- 明确记录人工批准、退回意见和时间；
- 未通过审核的产物不能进入公开发布队列。

## 通知与远程控制

远程入口只接受固定命令与已知参数，不把自然语言直接拼接成 shell 或任意 API。

当前 Alpha 的主要边界是回环地址与 Origin 绑定。带 Origin 的请求必须命中 allowlist；无 Origin 的本机 CLI、伴生脚本或进程被视为同一操作系统用户并可调用写接口。因此，该入口不是可安全暴露到网络的远程认证 API。

如果配置共享密钥，所有收件和遥控请求都必须携带并通过以下签名头；省略任一签名头不会降级为 Origin 信任：

~~~text
X-Zhitai-Timestamp: Unix 时间
X-Zhitai-Nonce: 随机且一次性
X-Zhitai-Signature: v1=HMAC-SHA256(timestamp + "." + nonce + "." + rawBody)
~~~

签名模式验证时间窗、nonce 重放和常量时间比较。明确未配置共享密钥时，服务端只接受精确 allowedOrigins，或无 Origin 且来自回环地址的同用户本机客户端；这一兼容模式不能防御同用户恶意进程。集成远程通知通道时仍应在连接器侧使用固定发送者、固定命令、最小对话权限和必要的二次确认。审计记录应保留动作与结果，不保留不必要的原始私聊。

## 发布适配器

支持三个逻辑模式：

- workbench_draft：只在织台内保存；
- platform_draft：尝试创建平台草稿；
- publish：请求公开发布。

默认应使用工作台草稿或平台草稿。publish 需要用户在可见界面中确认素材、标题、账号、平台、可见范围和时间，并携带操作确认标记。

排期任务需要持久化、幂等、重启恢复和过期处理。验证码、登录失效、平台风控、账号异常或不确定退出码应进入 needs_attention，不循环重试。

## 浏览器用户脚本

织台只定义与页面伴生脚本交互的最小消息契约。用户脚本必须有明确许可证、最小域名匹配、可读源码、版本和数据流说明。

许可证不明确的第三方脚本不得复制、修改、合并或打包进织台，包括所谓“一体化”版本。可以保留独立适配器，让有合法来源和使用权的用户自行连接。

## 集成验收清单

- [ ] 上游地址、所选版本和许可证已记录；
- [ ] 默认关闭，不影响核心启动；
- [ ] 只绑定回环，使用最小文件和账号权限；
- [ ] 无真实账号即可运行契约测试；
- [ ] Cookie、Token、二维码和原始响应不会泄漏；
- [ ] 状态区分安装、进程、健康、登录和业务成功；
- [ ] 失败、验证码和风控会停止并转人工；
- [ ] 公开发布与服务控制保留现有确认门，新增高影响动作另有预览、显式确认、幂等和审计；
- [ ] 升级可预览和回滚；若缺少发布者签名或强校验和，已明确警告并提供人工核验方式；
- [ ] 文档没有暗示织台分发或担保第三方工具。
